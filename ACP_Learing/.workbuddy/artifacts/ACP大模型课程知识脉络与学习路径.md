## 一、一句话结论

本课程不是一个"知识清单"，而是一个**完整项目的工程闭环**：以"新人答疑机器人"为贯穿主线，按「能用 → 好用 → 可靠 → 上线」的顺序，把大模型应用从一行 API 调用带到生产环境，每一步都是上一步暴露问题后的自然延伸。

## 四、知识递进逻辑（课程设计精髓）

每章出现都不是凭空设计，而是**上一步做完后遇到新问题**自然引出：

```
让机器人开口说话（2.1 API）→ 算清第一笔账
  ↓ 知识不够：私域问题答不了
给它知识、教规范、建评测（2.2 RAG / 2.3 Prompt / 2.4-2.5 评测优化）→ 质量可衡量
  ↓ 只会"说"不会"做"；经验不沉淀；系统不可靠
让它动手、规划、分工、记忆、沉淀（3.1-3.8 Agent 全栈）→ 可靠系统
  ↓ 成本、部署、安全
蒸馏小模型 + 部署 + 生产实践 + 安全合规（4.1-4.4）→ 走向生产
  ↓ 如何判断业务价值
RIDE 方法论与总结（5.1-5.2）→ 独立设计 AI 解决方案的能力
```

**核心方法论贯穿**：Prompt（2.3）→ Skill（3.5）→ Harness（3.8）→ RIDE（5.1），是一条"从技巧到工程再到业务判断"的升华主线。

## 六、三条推荐学习路径

### 路线 A · 系统性完整学习（推荐）
C1 → C2 → C3 → C4 → C5 逐课推进，每课时在 DSW 中跑通代码 + 完成课后小测验 + 记录笔记。
- 收益最大：形成完整工程闭环认知，为面试和方案设计打底
- 适合：备考 ACP 认证 + 打算长期深耕大模型应用开发的学员

### 路线 B · 备考冲刺（时间有限）
按权重投入：2.4/2.5（检索 20%）→ 2.1（开发 17%）→ 4.1/4.2（微调部署 16%）→ 3.1/3.3（Agent 16%）→ 2.3（提示词 15%）。
- 用每章「课后小测验」自查，错题回看对应 Notebook
- 3.8 与 3.7 可不深究（偏前沿、公开内容少）

### 路线 C · 实战驱动（以项目为主线）
先跑通 2.1 API → 叠加 RAG（2.2）→ 评测（2.4）→ Agent（3.1）→ Skill（3.5）→ 蒸馏部署（4.1/4.2），边做边补理论。
- 适合：已有 Python/LLM 经验、以"能交付"为目标的开发者

## 七、学习建议与自检清单

1. **环境先行**：先完成 1.1，在 DSW 里验证 `python -c "from config.load_key import load_key; load_key()"` 通过再开课。
2. **代码必跑**：课程代码直接复用 `course_core/chatbot` 模块，动手改参数（temperature、切片方式、top_k）观察输出差异，是理解原理的最快路径。
3. **以评测为镜**：2.4 与 3.6 的评测体系是"质量可衡量"的关键，学完要能解释 answer correctness 与 context recall/precision 的区别。
4. **项目自检**：学完 C4 后，应能独立回答——为什么用 RAG 而不是微调？什么时候该蒸馏？Agent 记忆有哪四种？提示词注入如何防御？
5. **版本注意**：本仓库依赖锁定较新（LlamaIndex 0.14、LangChain 0.3、ragas 0.1.9），本地复现建议严格按 requirements.txt 安装。

# 会话存档

把 WorkBuddy 的**完整会话记录**归档到 GitHub，用于换电脑后继续对话，同时留下一份可读、可追溯的历史。

## 目录结构

```
会话存档/
├── README.md                      ← 本文件：存档说明 + 恢复方法
├── 工具/
│   ├── 导出会话.py                 ← 从本机 WorkBuddy 导出会话（含可读全文生成）
│   └── 恢复会话.py                 ← 把存档还原到本机 WorkBuddy，继续对话
└── <工作空间名>/
    ├── <会话标题>.md               ← 可读全文：对话 + 模型思考 + 工具调用与返回
    ├── 会话原始文件/                ← 原始会话文件（WorkBuddy 可识别的格式）
    │   ├── <会话ID>.jsonl
    │   ├── <会话ID>.meta.json
    │   └── <会话ID>.file-rollback.ndjson
    └── 工作空间存档/
        └── .workbuddy/              ← 该工作空间自带的记忆（memory）等
```

## 一、在新电脑上继续对话

### 1. 拉取本仓库

```bash
git clone https://github.com/NotSeriousCoder/WorkBuddyAgent.git
```

### 2. 确认工作空间路径

WorkBuddy 是按**工作空间绝对路径**来存放和查找会话的。最省事的做法是：
新电脑上把工作空间放在**和原电脑完全相同的路径**（例如 `G:\项目\WorkBuddy项目\东风日产组织分析`）。
路径不同也能恢复，但恢复时必须把「本机实际路径」传给恢复脚本（见下一步）。

### 3. 运行恢复脚本

```bash
cd WorkBuddyAgent\会话存档\工具
python 恢复会话.py --archive "..\东风日产组织分析" --workspace "G:\项目\WorkBuddy项目\东风日产组织分析"
```

脚本会把原始会话文件复制到 WorkBuddy 的会话目录：

```
%USERPROFILE%\.workbuddy\projects\<工作空间路径编码>\<会话ID>.jsonl
```

### 4. 重启 WorkBuddy

重新打开该工作空间，会话列表中即可看到这条会话，点开就能接着往下聊。

### 手动恢复（不用脚本）

1. 算出编码目录名：把工作空间绝对路径里的 `:` 和 `\` 全部换成 `-`，盘符改成小写。
   例：`G:\项目\WorkBuddy项目\东风日产组织分析` → `g-项目-WorkBuddy项目-东风日产组织分析`
2. 新建目录 `%USERPROFILE%\.workbuddy\projects\g-项目-WorkBuddy项目-东风日产组织分析\`
3. 把 `会话原始文件/` 里的三个文件原样复制进去
4. 重启 WorkBuddy

## 二、导出新的会话

在**存放了目标会话的那台电脑**上运行：

```bash
cd WorkBuddyAgent\会话存档\工具
python 导出会话.py --workspace "G:\项目\WorkBuddy项目\东风日产组织分析" --out "..\东风日产组织分析"
```

脚本会自动找到该工作空间的全部会话，产出可读全文，并连同原始文件、工作空间记忆一起归档。
然后 `git add / commit / push` 即可。

## 三、说明与注意事项

- **完整、不改写**：`.md` 全文中的对话、模型思考、工具调用与返回均为原样呈现，只把平台注入的 `<system-reminder>` 上下文折叠起来，保证问题与回答一眼可见；原始 `.jsonl` 则是逐条原始记录，一字未改。
- **可追溯**：想要 100% 的原始数据（含文件快照等），以 `会话原始文件/` 里的 `.jsonl` 为准。
- **不含任何密钥**：归档内容为对话与文件内容本身，不包含账号、token 等凭据。
- **会话是"接着聊"而不是"合并"**：恢复后是新电脑上的一条历史会话，继续对话产生的新内容会追加到该会话文件里；如需再次同步，重复「导出新的会话」即可。
- **路径依赖**：若新旧电脑的盘符/目录不同，恢复后 WorkBuddy 仍可打开该会话，但会话记录里保留的是原始工作空间路径，供参考。
